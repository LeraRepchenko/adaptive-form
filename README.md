# AdaptiveForm

Лабораторная работа №4. Размерные политики и адаптивные интерфейсы в Qt Widgets.

## Цель работы

Изучить механизм размерных политик `QSizePolicy`, научиться управлять распределением свободного пространства в layout с помощью `addStretch()`, задавать внутренние отступы и зазоры через `setContentsMargins() / setSpacing()`, и на этой основе строить адаптивные интерфейсы, которые корректно меняют размер и компоновку при растяжении и сжатии окна.

## Постановка задачи

Реализовать приложение-анкету **AdaptiveForm**:
1. Форма на `QFormLayout` с полями: Имя, Email, Возраст, Страна, Описание, Согласие.
2. Поле «Описание» тянется по вертикали и забирает свободное место.
3. Поле «Возраст» зафиксировано по ширине и обёрнуто в пружину (`addStretch`).
4. Кнопки действий (`OK`/`Отмена`) прижаты вправо через `addStretch()`.
5. Панель режимов для переключения политик и отступов на лету.
6. Кнопки дампа политик и размеров.
7. Логирование `resizeEvent()` в консоль.

## Теоретическое обоснование 

**Зачем нужны Layout.** Ручная расстановка через `setGeometry()` неадаптивна: при изменении размера окна виджеты перекрываются. Layout (`QBoxLayout`, `QFormLayout`, `QGridLayout`) сам пересчитывает геометрию, опираясь на «желания» виджетов.

**sizeHint и minimumSizeHint.** `sizeHint()` — комфортный желаемый размер. `minimumSizeHint()` — предел сжатия. Layout уважает минимум всегда, а «хотелку» — насколько позволяет место.

**QSizePolicy.** У виджета две независимые оси (горизонтальная и вертикальная). Основные флаги: 
*   `Fixed` — не тянется.
*   `Minimum` — не сжимается ниже sizeHint.
*   `Maximum` — не растет выше sizeHint.
*   `Preferred` — желаемый sizeHint, может расти и сжиматься.
*   `Expanding` — активно забирает всё свободное место.
*   `Ignored` — игнорирует sizeHint.

**Распределение места.** Сначала каждому выделяется минимум. Остаток делится между теми, кто может расти (Preferred, Expanding и др.), пропорционально их «аппетиту» и stretch-факторам. Fixed-виджеты излишка не получают — отсюда и появляется пустота, если нет `addStretch`.

**addStretch() и отступы.** `addStretch()` — невидимая пружина (Expanding), которая забирает свободное место и прижимает виджеты к краям. `setContentsMargins()` задает отступы от краев контейнера, `setSpacing()` — зазор между элементами. Важно не допускать «двойных отступов» у вложенных layout.

**События без Q_OBJECT.** Для переопределения `resizeEvent()` или `paintEvent()` макрос `Q_OBJECT` не нужен — это обычный полиморфизм C++. Он нужен только для сигналов и слотов.

2. Собрать проект (молоток).
3. Запустить (зелёный треугольник).

## Что демонстрирует программа

*   **QSizePolicy:** «Имя», «Email», «Страна», «Описание» — `Expanding` по горизонтали. «Описание» — `Expanding` по вертикали. «Возраст» и чекбокс — `Fixed`.
*   **addStretch:** прижимает «Возраст» влево, кнопки режимов влево, кнопки OK/Отмена вправо.
*   **Отступы:** кнопки «Компактный» и «Развёрнутый» переключают `margins` и `spacing` на лету.
*   **Логирование:** `[CREATE]`, `[POLICY]`, `[RESIZE]`, `[MARGIN]`, `[TOGGLE]` выводятся в консоль.

## Кнопки и режимы

| Кнопка | Действие |
|--------|----------|
| Компактный | margins=8, spacing=4 |
| Развёрнутый | margins=24, spacing=12 |
| Описание: тянуть/фикс. | Переключить вертикальную политику описания |
| Возраст: фикс./тянуть | Переключить горизонтальную политику возраста |
| Дамп политик | Вывести политики всех полей в консоль |
| Дамп размеров | Вывести текущие размеры и sizeHint |
| OK | Вывести данные формы и закрыть |
| Отмена | Закрыть окно |

### Лог при запуске и растяжении окна
```
[CREATE] "Имя" (AdaptiveLineEdit)
[CREATE] "Email" (AdaptiveLineEdit)
[CREATE] "Возраст" (AdaptiveLineEdit)
[CREATE] "Описание" (AdaptiveTextEdit)
```

## Разбор ошибок и их решений

**Ошибка 1. `multiple definition of ...`**
Компиляция прошла, линковка упала. Причина: `.cpp` файлы попали в сборку дважды (в `.pro` были указаны дубли). Решение: удалить дубли из `.pro`, удалить папку `build` и пересобрать.

**Ошибка 2. Двойные отступы.**
Если не обнулить margins у `QFormLayout`, то к отступам основного layout прибавятся отступы формы. Решение: `m_formLayout->setContentsMargins(0, 0, 0, 0);`.

**Ошибка 3. Виджет не тянется.**
Если у поля нет `Expanding` политики и нет пружины `addStretch`, оно останется фиксированного размера. Решение: задать правильную `QSizePolicy` и использовать `addStretch`.

## Вывод

В ходе работы изучены механизм `QSizePolicy` и способы управления адаптивностью интерфейса. Освоены методы `addStretch()`, `setContentsMargins()`, `setSpacing()`, а также логирование размеров через `resizeEvent()`. Понято, что для адаптивности по каждой оси нужен хотя бы один растягиваемый элемент. Также усвоено, что `Q_OBJECT` не нужен для переопределения виртуальных событий (`resizeEvent`), но обязателен для сигналов и слотов.

## Ответы на контрольные вопросы

**1. Как заставить поле ввода тянуться по ширине вместе с окном?**
Задать ему горизонтальную политику `QSizePolicy::Expanding` (или `MinimumExpanding`).

**2. Как прижать кнопки «ОК / Отмена» к правому краю, чтобы они не растянулись на всю ширину?**
Поместить их в `QHBoxLayout`, добавив перед ними пружину `addStretch()`. Пружина заберёт всё свободное место, прижав кнопки вправо. Самим кнопкам оставить политику `Fixed` или `Minimum`.

**3. Как задать между двумя группами виджетов зазор, который растёт вместе с окном, а как – фиксированный?**
Растущий зазор — `addStretch()` (или `QSpacerItem` с `Expanding`). Фиксированный — `addSpacing(px)` (или `QSpacerItem` с `Fixed`).

**4. Как задать виджету размер, ниже которого layout его не сожмёт?**
Вызвать `setMinimumSize(w, h)` или переопределить `minimumSizeHint()`. Layout всегда уважает минимум.

**5. Как уменьшить отступы от краёв окна до содержимого?**
У основного layout окна вызвать `setContentsMargins(left, top, right, bottom)` с меньшими значениями (например, 8, 8, 8, 8).

**6. Как убрать двойные отступы, когда форма вложена в основной layout?**
У вложенного layout (например, `QFormLayout`) вызвать `setContentsMargins(0, 0, 0, 0)`. Тогда отступы будут задаваться только основным layout.

**7. Как построить двухколоночную форму «подпись: поле»?**
Использовать `QFormLayout`. Добавлять строки через `addRow("Подпись:", widget)`.

**8. Как в такой форме оставить одно поле коротким, а остальные – тянущимися?**
Короткому полю задать политику `Fixed`. Чтобы оно не растянулось на всю ширину колонки, обернуть его в `QHBoxLayout`: положить поле и добавить `addStretch()`.

**9. Как поменять политику виджета «на лету» и чтобы эффект наступил сразу?**
Прочитать текущую `QSizePolicy`, изменить нужную ось (гориз./верт.), применить через `setSizePolicy()`, а затем вызвать `updateGeometry()` — это заставит layout пересчитать размеры немедленно.

**10. Как заставить многострочное поле расти по высоте вместе с окном?**
Задать ему вертикальную политику `QSizePolicy::Expanding`. Важно, чтобы выше по иерархии (в корневом layout) не было других элементов, забирающих всё место, или чтобы их «аппетит» был меньше.

**11. Как в логе убедиться, что конкретное поле реально меняется при растяжении окна?**
Переопределить `resizeEvent()` в классе этого поля (или в главном окне) и выводить новые размеры (`event->size()`) в консоль через `qDebug()`. Растягивая окно, вы увидите, как меняются цифры.

**12. Как вывести текущие политики и размеры всех полей, чтобы отладить вёрстку?**
Создать кнопку (или слот), которая пройдётся циклом по списку нужных виджетов и выведет через `qDebug()` их `sizePolicy().horizontalPolicy()`, `sizePolicy().verticalPolicy()`, `width()`, `height()`, `sizeHint()` и `minimumSizeHint()`.
